# AI 研究 Agent 与每日复盘设计

日期：2026-08-12

## 1. 目标与定位

在应用全局顶部新增一个内置 AI 研究 Agent，为 A 股提供三类能力：

1. 解释现有技术信号、市场术语和指标组合，内置知识可在 AI 不可用时继续工作。
2. 基于全 A 股量化预筛和多维证据，每个交易日给出最多 5 只值得进一步关注的股票及完整分析理由。
3. 对 Agent 自己历史上给出的推荐进行逐交易日复盘，保留原始判断并分析后续表现、论据变化与判断偏差。

Agent 的定位是“研究分析与选股辅助”，不是固定交易规则引擎。任何单一指标、阈值或量化得分都不能直接等同于买入或卖出。Agent 可以根据真实数据给出偏买入、观察、偏卖出或回避的分析倾向，也可以给出参考关注区间和风险位置，但不接入券商、不自动下单、不代替用户做最终投资决策。

首版默认风格为保守型，判断周期为 5～20 个交易日。

## 2. 首版范围

### 2.1 包含

- 全局顶部紧凑输入框和右侧 Agent 抽屉。
- AI 问答、指定股票分析、今日选股、历史推荐和推荐复盘。
- A 股全市场量化预筛，AI 从候选池中深度比较后选出最多 5 只。
- 技术面、情绪面、信息面、基本面、行业强度和资金/热度等本地扩展数据的证据聚合。
- 巨潮资讯公告元数据补充，以及普通新闻 Provider 接口预留。
- 推荐后每日复盘，以及第 5、10、20 个交易日的阶段总结。
- 自动任务和手动重新分析/复盘。

### 2.2 不包含

- 港股、美股或其他市场的 Agent 选股；首版仅覆盖 A 股。
- 用户持仓、账户、真实成交或个人盈亏复盘。
- 券商连接、自动下单、条件单或自动交易。
- 把某一技术信号固化为必然买卖规则。
- 通用互联网搜索、社交媒体舆情抓取或不稳定新闻网页抓取。
- 需要新增 Token 或额外付费权限的新闻服务。

## 3. 总体架构

```text
全局 Agent 入口
  ├─ 术语/信号问题 ─────────> 内置研究知识库 ──> 确定性解释
  ├─ 指定股票问题 ─────────> 证据聚合器 ─────> AI 流式分析
  └─ 今日选股/自动任务
       └─ 全 A 股数据仓库
            └─ 资格过滤 + 多维量化预筛（约 20～30 只）
                 └─ 证据聚合器
                      └─ AI 结构化比较（最多 5 只）
                           ├─ 不可变推荐记录
                           └─ 每日复盘 + 5/10/20 日阶段总结
```

新增模块必须通过现有 repository/provider 读取数据，不能从业务服务直接绕过仓库调用 TickFlow。现有个股分析、大盘复盘和财务分析接口的提示词与行为保持不变；研究 Agent 使用独立服务、独立数据契约和独立持久化文件。

## 4. 前端交互

### 4.1 全局顶部入口

在现有 `Layout` 主内容区域顶部增加紧凑 Agent 栏，保持侧边栏和各看板布局不变。

- 默认展示一行输入框，提示语类似“问信号、分析股票或查看今日选股”。
- 支持股票代码、股票名称和自然语言。
- 提供“今日选股”“解释 MACD 金叉”“分析一只股票”等快捷入口。
- 提交问题或点击快捷入口后打开右侧抽屉；窄屏使用全屏 Sheet。
- Agent 正在生成时，用户关闭抽屉不会终止任务；复用现有全局任务 Store 与流式 Markdown 展示模式。

### 4.2 抽屉结构

抽屉包含三个页签：

1. **AI 问答**：术语解释、信号组合解释、指定股票分析和追问。
2. **今日选股**：展示当前交易日最多 5 只推荐及数据状态。
3. **推荐复盘**：默认展示今日复盘总览，并可按推荐批次、股票和交易日展开历史轨迹。

每张推荐卡至少展示：

- 股票名称、代码、分析倾向和置信度。
- 技术面、市场情绪、行业/概念、基本面和信息面的主要证据。
- 核心逻辑、潜在催化、反向证据与主要风险。
- 5～20 个交易日的判断假设。
- 有充分数据时展示参考关注区间和风险位置，并明确标为分析推断。
- 数据截止时间、证据来源、公告原文链接和缺失数据提示。

同一数据日期重复点击“今日选股”默认复用已保存结果。用户明确点击“基于最新数据重新分析”时生成新版本，旧版本继续保留。

### 4.3 内置术语交互

首版知识库覆盖仓库已有的均线、MACD、突破/跌破、布林带、放量、涨跌停、炸板/修复和分时均价线等信号，同时补充 RSI、波动率、量价背离、市场宽度、相对强弱、估值和财务质量等推荐报告会使用的术语。

- 精确命中术语时优先返回知识库答案，不消耗 AI。
- 每条解释包含“定义、通常如何理解、不能单独说明什么、与哪些证据结合观察”。
- 推荐卡中的术语可点击展开同一份解释，避免前后口径不一致。
- AI 可以在知识库答案上结合上下文扩展，但不能把单一信号描述为确定买卖结论。

## 5. 全市场量化预筛

量化预筛的职责只是缩小 AI 的研究范围，不直接产生买卖结论。

### 5.1 资格过滤

默认排除：

- 名称包含 ST、*ST 或退市整理标识的股票。
- 最新交易日停牌、无有效价格或无成交量的股票。
- 上市时间过短、历史 K 线不足 60 个交易日的股票。
- 流动性处于市场末端且无法支持正常研究口径的股票。
- 关键行情数据明显滞后或核心字段缺失的股票。

所有过滤原因需要可统计、可测试，并在“候选生成说明”中显示汇总数量。

### 5.2 多维排序

对通过资格过滤的股票按市场横截面分位数归一化，再组成候选排序。维度包括：

- 趋势与中期动量。
- 均线、MACD、RSI、关键位和已有信号的一致性。
- 量价配合、波动率、近期极端涨跌和追高风险。
- 大盘情绪、市场宽度、涨停/炸板等环境状态。
- 所属行业和概念的相对强弱。
- 财务质量、成长性、盈利质量和估值风险。
- 本地扩展数据中的资金、热度、研究评分等可用信息。

保守型风格会提高对流动性、趋势稳定性、证据一致性和回撤风险的重视，并对极端波动、短期过热和证据冲突做惩罚。维度权重和版本写入推荐快照，但任何分数阈值都不能直接映射为“买入”或“卖出”。

预筛最终向 AI 提供约 20～30 只候选，以及必要的结构化摘要，不把全市场原始数据或几千只股票的完整 K 线发送给模型。

## 6. 多维证据聚合

证据聚合器为“指定股票分析”和“每日候选比较”复用同一份数据契约：

### 6.1 技术面

- 最新价格、不同周期收益、趋势与均线结构。
- MACD、RSI、布林带、成交量、波动率和量价关系。
- 近期关键高低点、支撑/压力参考和已有信号。
- 数据日期、复权口径和计算窗口。

### 6.2 情绪与市场环境

- 市场宽度、涨跌分布、涨停/跌停、炸板和修复状态。
- 大盘情绪分层、当前市场状态和主要指数表现。
- 股票所在行业、概念的强弱与热度变化。

### 6.3 基本面

- 已有财务指标、成长性、盈利质量、现金流、估值和异常风险。
- 数据期末与披露时间分开记录，避免把旧财报当成最新事实。
- 缺少财务数据时明确降级，不用行业均值伪造个股数据。

### 6.4 信息面

- 首选本地扩展数据中的研究评分、资金、热度和情绪信息。
- 通过独立 `AnnouncementProvider` 补充巨潮资讯公告的标题、日期、分类和原文链接。
- 首版只把公告元数据和明确提取的结构化事实交给 AI；外部文本视为不可信内容，不能改变系统指令。
- 普通新闻定义 `NewsProvider` 接口但首版使用空实现，待未来配置稳定数据源后接入。

每条外部证据必须带来源和日期。公告查询超时、限流或接口变化时，报告显示“公告补充暂不可用”，不能阻止本地分析，也不能让 AI 编造新闻或事件。

## 7. AI 判断与输出契约

### 7.1 每日推荐

AI 只能从量化候选池中选择股票，并输出严格结构化结果。每只推荐必须包含：

- `symbol`、`name`、`stance`、`confidence`。
- 分维度结论与证据引用。
- 推荐逻辑、潜在催化、反向证据和风险。
- 5～20 日判断假设、失效条件。
- 可选的参考关注区间和风险位置，以及它们的实际数据依据。
- 数据截止日期和信息缺失列表。

`stance` 仅允许“偏买入、观察、偏卖出、回避”。如果合格股票少于 5 只，AI 可以返回更少的股票，并解释未满 5 只的原因。不能为了凑数而推荐。

AI 文本先经过 Pydantic 契约校验；格式错误时只允许做一次修复重试。仍不合格、引用候选池外股票或缺少必填反向证据时，本次结果不保存为正式推荐。

### 7.2 指定股票分析

指定股票不要求来自当日候选池，但必须是仓库可识别且有足够数据的 A 股。回答沿用同一证据结构，先说明数据完整度，再给分析倾向、支持证据、反向证据、风险和需要继续观察的验证点。

### 7.3 AI 不可用时

- 术语解释仍可使用。
- 量化预筛结果可以显示为“研究候选”，但不能冒充 AI 正式推荐。
- 今日选股和指定股票 AI 结论显示明确错误与重试入口。
- 不复用过期结果伪装为当日新分析；历史结果必须显示原始数据日期。

## 8. 推荐记录与每日复盘

### 8.1 不可变推荐批次

每次正式推荐保存一个不可变批次，包含：

- 唯一批次 ID、交易日、生成时间和触发方式。
- 数据快照日期、市场状态和候选筛选摘要。
- 模型、提示词版本、预筛版本和保守型配置版本。
- 候选池及最多 5 只正式推荐的完整原始结果。
- 强制重新分析时的父批次 ID 和新版本号。

后续复盘只能通过新记录引用推荐批次，不能回写或修改原始理由。

### 8.2 每日复盘

每个交易日行情同步成功后，更新所有推荐后未满 20 个交易日的股票：

- 当日收益、推荐以来累计收益。
- 推荐以来最大上涨、最大回撤。
- 同期沪深 300 收益和相对表现。
- 原始技术、量价、市场情绪、行业强度、财务和公告论据的变化。
- 新增支持证据、反向证据、风险和信息变化。
- 判断状态：增强、维持、减弱、失效。
- AI 对自身判断的复盘：哪些证据有效、遗漏了什么、是否存在追涨、过度依赖单一指标或忽略市场环境等偏差。

第 5、10、20 个交易日额外生成阶段总结。阶段总结聚合此前逐日轨迹，不替换逐日记录。

收益指标不是模拟成交结果。推荐统一以报告所引用的最近完整交易日收盘价为观察基准，第 1 个复盘日是其后的第 1 个有效交易日；个股与沪深 300 使用相同起止日期和前复权口径。累计收益按复权日收益连乘，最大上涨取观察期累计收益峰值，最大回撤取观察期净值从历史峰值到后续低点的最大跌幅。若基准指数在某日缺数，当日相对表现标记不可用，不用自然日或邻近日期替代。

若应用在某个交易日未运行，下次同步可以回填有历史行情支持的客观收益指标；AI 叙述只使用能够按当时日期截断的证据，并标记为“补算”。无法可靠还原的信息维度标记缺失，不做事后编造。

## 9. 存储设计

推荐与逐日复盘需要长期追加、按批次关联和幂等更新，不适合沿用会按条数裁剪的通用报告 JSON。因此新增专用 `ResearchAgentStore`，使用 Python 标准库 SQLite，数据库路径为 `data/user_data/ai_research_agent.db`，不修改现有三类 AI 报告文件。

核心表：

- `schema_meta`：数据库 schema 版本。
- `recommendation_batches`：不可变推荐批次、数据快照日期、版本关系、模型和筛选配置。
- `recommendations`：批次内最多 5 只股票的结构化结论与原始证据快照。
- `daily_reviews`：逐日客观指标和 AI 复盘，以 `batch_id + symbol + trade_date` 为唯一键。
- `stage_reviews`：第 5、10、20 个交易日阶段总结，以 `batch_id + symbol + stage_day` 为唯一键。
- `agent_runs`：自动/手动任务状态、错误摘要和重试信息，不保存凭证或完整上游异常。

结构化高频检索字段单独建列，证据快照和 AI 结果使用带 `schema_version` 的 JSON 文本列。写入使用显式事务、外键和唯一约束；推荐批次一旦完成就只读，重新分析创建带父批次 ID 的新版本。逐日复盘允许在同一唯一键上补齐客观字段或把失败状态更新为成功，但不能更新原始推荐。

首版不自动删除推荐和复盘历史。未来如果需要归档或清理，必须提供显式用户操作和可恢复导出，不能因达到固定条数而静默裁剪。

首版问答历史只保存在前端当前会话 Store，不落盘；正式推荐和复盘始终由后端持久化。

## 10. API 与服务边界

新增独立路由 `/api/research-agent`：

- `GET /terms`：获取术语索引或指定术语解释。
- `POST /chat`：指定股票或研究问题的 NDJSON 流式回答。
- `GET /recommendations/latest`：读取最新正式推荐批次。
- `GET /recommendations`：分页读取历史批次。
- `POST /recommendations/run`：手动运行；默认幂等复用，`force=true` 时创建新版本。
- `GET /reviews`：按批次、股票或日期读取复盘。
- `POST /reviews/run`：手动运行当日复盘或补算缺失交易日。
- `GET /status`：返回当前任务、最新数据日期、最后成功时间和降级原因。

API 层只负责请求校验、权限沿用、流式封装和错误映射。候选筛选、证据聚合、AI 结构校验、存储和复盘计算分别置于服务层，避免路由直接读取 Parquet、访问 TickFlow 或拼接复杂提示词。

## 11. 自动任务与并发

- 日行情流水线成功且 repository 缓存刷新完成后，向研究 Agent 编排器提交同一交易日的幂等任务。
- 自动任务先完成历史推荐复盘，再判断当天是否已有正式推荐；没有时再生成当日推荐。
- 手动按钮调用同一编排器，不另建一套逻辑。
- 同一时间只允许一个全市场预筛/推荐任务运行；相同交易日请求复用现有任务状态。
- `force=true` 只绕过推荐结果复用，不绕过全局 single-flight，也不重复写相同日期的复盘。
- AI 或公告服务失败不会使行情流水线失败；错误记录在 Agent 状态中并允许手动重试。
- 应用关闭时停止 Agent 后台任务并释放线程/协程，不留下孤立进程。

## 12. 安全、信息边界与免责声明

- 不在提示词、日志、响应或持久化文件中写入 API Key、Token 或用户秘密。
- 公告 Provider 只访问配置允许的巨潮域名，不接受 AI 生成的任意 URL，避免服务端请求伪造。
- 上游错误经过统一归一化，不把凭证、命令行参数或完整请求细节返回前端。
- 外部公告标题和内容只能作为数据，不能作为模型指令。
- 每份推荐和分析均显示数据日期、缺失维度和“仅供研究参考，不构成自动交易指令”的说明。
- Agent 不假设用户持仓、成本、资金规模或风险承受能力；首版只使用已确认的保守型默认风格。

## 13. 失败与降级规则

| 场景 | 行为 |
| --- | --- |
| AI 未配置或调用失败 | 术语可用、展示量化候选但不生成正式推荐 |
| 合格候选不足 | 返回少于 5 只并解释原因 |
| 指定股票数据不足 | 不给倾向，列出缺失项和可用事实 |
| 巨潮查询失败 | 本地分析继续，信息面标记降级 |
| 部分财务/扩展数据缺失 | 保留其他维度，降低置信度并显示缺失项 |
| AI 结构校验失败 | 修复一次，仍失败则不持久化 |
| 自动任务重复触发 | 复用同一交易日任务和结果 |
| 存储损坏 | 停止写入并提示排查，不用空文件覆盖 |
| 行情日期滞后 | 不生成“今日”推荐，显示最新可用数据日期 |

## 14. 测试矩阵

### 14.1 后端单元测试

- 术语别名、精确命中和无 AI 降级。
- ST、停牌、次新、低流动性和数据不足过滤。
- 横截面归一化、保守型风险惩罚、候选数量和稳定排序。
- 各证据维度的数据日期、缺失值和来源标记。
- AI 结果契约、候选池约束、少于 5 只、修复重试和拒绝保存。

## 15. 成功标准

- 用户可在任意主要页面通过顶部入口打开 Agent，并获得一致的术语解释。
- Agent 可分析任意数据充分的 A 股，也能从全 A 股中给出最多 5 只具备多维证据的每日推荐。
- 每个结论都有支持证据、反向证据、风险、来源、数据日期和缺失项，不把单一信号当作交易规则。
- 历史推荐不可篡改；推荐后的每个可用交易日都有客观表现和论据变化记录，并在第 5、10、20 日形成阶段总结。
- AI、公告或部分数据不可用时明确降级，不伪造结论，不影响现有看板与行情流水线。
- 不接入真实交易，不泄漏凭证，不破坏已有 A 股、美股、策略、监控和分析功能。
